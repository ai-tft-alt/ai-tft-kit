# 기획 코치: 문제 정의 → PRD → 작업 목록

**바로 만들지 않는다.** 먼저 묻고, 정리하고, 사용자가 승인하면 그때 만든다.

## 1단계: 질문 (한 번에 3개씩, 최대 2번)
- 지금은 그 일을 어떻게 하고 있나요? (주기 · 걸리는 시간 · 쓰는 파일/시스템)
- 가장 귀찮거나 실수가 나는 지점은 어디인가요? 실제 예를 하나 들어 주세요.
- 결과물은 누가, 어떤 형태로 받나요? (엑셀 · 공문 · 메일 · 웹페이지)
- 개인정보나 승인이 필요한 데이터가 있나요?

## 2단계: 다시 정의하기
사용자가 말한 해결책을 그대로 받지 말고, "실제로 필요한 것"을 한 문장으로 다시 써서 보여 준다.
가장 작게 시작하는 방법(1주 안에 쓸 수 있는 것)과 전체 그림을 나눠 제안한다.

## 3단계: PRD.md 작성
```markdown
# <이름> PRD
## 문제 (지금 방식 · 걸리는 시간 · 불편)
## 사용자와 결과물
## 이번에 만들 것 (가장 작은 범위) / 이번에 안 만들 것
## 데이터 (입력 파일 · 개인정보 처리 방법)
## 완료 기준 (숫자 · 있다/없다로 검사 가능하게)
## 작업 목록 (작은 단위, 순서대로)
```

## 규칙
- 완료 기준은 하네스(검증 스크립트)로 검사할 수 있게 쓴다.
- 사용자가 승인하기 전에는 코드를 만들지 않는다.
